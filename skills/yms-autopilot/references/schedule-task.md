# 定时任务 · schedule-task

> 准备把一条手动跑稳了的流程交给定时任务时，先把指令写清楚。写不清的地方，就是它半夜会出错的地方。
> 来自《AI 投资指南》02 基建篇 §四 · 可带走资产二 · 07 Agent 篇 §二
>
> 属于 `yms-autopilot` 模块。也可以单独把这份复制进任何 AI 对话里，帮你起草任务说明。

## 它做什么，不做什么

- 做：把一条手动跑稳的流程写成一份任务说明（什么时候跑、先读什么、做什么、写到哪、怎么算完成、依赖谁、漏了怎么办、出错怎么办、红线）；任务多了，合成一张按依赖排的调度表，再帮你从「一堆闹钟」平滑切过去。
- 不做：不在没人看着的时候创建或启停定时任务，不在任务里放任何下单能力，不替你决定哪条流程该自动化。

## 前置检查

| 要确认 | 怎么确认 | 不满足怎么办 |
|:---|:---|:---|
| 这条流程手动跑满三期 | 数产物目录里不同日期的文件 | 不满三期 → 停下，说清现在几期；我坚持的话起草，但标「未满三期，先手动」 |
| 手动跑时我说的那句话 | 问我，或从对话 / 产物里找 | 任务的「做什么」要和手动跑时说的一致 |
| 我用的工具有没有定时任务 | 问我 | 没有 → 照样写说明，每天手动跑同一条，一样能积累 |
| 已有的任务说明和调度表 | `07_主控/任务说明/`、`07_主控/调度表.md` | 不存在就建 `07_主控/` |

## 步骤

**1. 写任务说明**

和我一起把下面每一项填完，空着的不算写完：

```markdown
【任务名】：（例：每日观测）
【什么时候跑】：（例：交易日收盘后；非交易日不跑；按哪个市场的交易日历）
【先读什么】：（例：说明书、01_我的投资框架/、上一份每日观测）
【做什么】：（和我手动跑时说的话一致；用到哪个 Skill 的哪个动作，写清楚，例：用 yms-watch 的每日变化）
【写到哪】：（例：03_每日观测/YYYY-MM-DD_每日观测.md）
【怎么算完成】：（例：上面这个文件存在，且包含「今天的变化」一节）
【依赖谁】：（例：要等上游 X 的产物出来；没出来就等，不用旧数据）
【用什么模型】：（动脑的活用强模型；只是检查、搬运用便宜的）
【一天最多试几次】：（例：2 次）
【漏跑了怎么办】：只补最近一期，文件开头注明「补跑」，不逐天补
【出错怎么办】：在 07_主控/回执/ 写一张回执：哪一步失败、原因是什么；不编造结果
【红线】：不下单；不修改 01_我的投资框架/ 和 04_决策与交易记录/；外部信息标来源；
          不确定的写「待核实」；不在运行中向我提问（没人看着）
```

写到 `07_主控/任务说明/<任务名>.md`。

**2. 权限提前配好**
定时任务在没人看着的时候跑。哪一步要人点一下「允许」，它就卡在哪一步，后面的全空。所以：
- 列出这条任务要用到的权限（读写哪些目录、要不要联网、要不要跑脚本），让我在工具里配好；
- 配完之后，看第一次真实运行的记录，确认它真的按设置在跑，不只看设置页。

**3. 建任务（我来，或我明确让你来）**
把要粘贴进工具定时任务界面的内容整理好：名字、时间、完整指令（就是上面那份说明）。我自己建；我在对话里明确说「帮我建」，才在这次对话里帮我建。

**4. 任务多了，合成调度表**
有三四条以上、或者开始出现「上游晚了几分钟、下游读到旧数据」，就该从一堆闹钟换成一张表：

```text
调度表
├─ 早盘批（周一至周五 · <开批时间> 开批 · <截止时间> 截止）
│    任务 A → 任务 B → 任务 C ∥ 任务 D
├─ 盘后批（交易日 · 收盘后开批）
│    任务 E → 任务 F
└─ 周末批（周日 · 下午开批）
     任务 G → 任务 H

（→ 表示等上游出完再跑；∥ 表示互不依赖、同时跑）
```

表里每个任务只写五件事：**依赖谁、看哪个文件算做完、用什么模型、完整指令在哪（任务说明的路径）、一天最多试几次。**

再配一个调度任务，按表执行：
- 只在可能有活的时段醒，每小时一次：谁该跑了、谁漏了、谁失败要重试。大多数拍是空的，回一句「没活」就结束，要轻；
- 做没做完看文件，不信任务自己说的；
- 交易日历它自己判断；临时休市这类规则外的情况，写下跳过的原因；
- 失败、重试用完、过了截止还没出 → 写回执，不问我；
- 每次开始、完成、失败都记时长，写进 `07_主控/调度日志/`。

调度表写到 `07_主控/调度表.md`。

**5. 一批一批切过去**
- 先开「影子模式」：调度只记录「本来会跑什么」，旧任务照常跑，对照几天；
- 对得上了再切成真跑，**同时**停掉对应的旧任务——两边只能开一边，不然同一份报告会被写两次；
- 停旧任务由我来做。

## 输出

- `07_主控/任务说明/<任务名>.md`
- 任务多了：`07_主控/调度表.md`
- 对话里：要我在工具里配的权限清单、要粘贴的任务内容、切换计划（哪天开影子、哪天切真跑、停哪几个旧任务）。

## 红线

- 不满三期不建议挂定时。
- 任务说明里写死红线，不放任何下单或交易能力。
- 无人值守时不创建、不启停定时任务，不提问。
- 不在任务说明里写密钥。

## 我自己的样本

我的定时任务原来是一个个加出来的，各自定一个时间，靠时钟对齐上下游：上游晚了五分钟，下游照样到点开跑，读到的是昨天的东西；某天一个任务挂了，后面一串都在用旧数据，我要到看报告时才发现。后来改成一份调度表，常开的定时任务从十几个收敛到 4 个：一个调度、一个晚上的主控心跳、一个白天巡检（上午傍晚各看一眼有没有缺报告），还有一个管我别的事情的心跳。

踩过的坑：无人值守时权限没配好，任务卡在一个确认框上，没人点，后面整串都不跑。电脑睡着了也不跑——这套东西跑在我自己的电脑上，这是本地优先的代价，我接受。
