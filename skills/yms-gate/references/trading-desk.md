# 操盘台 · trading-desk

> 你不是软件的用户，是自己操盘台的产品经理。工具长成什么样，取决于你最常在哪一步犯错。
> 来自《AI 投资指南》05 操盘层 §一–四 · 可带走资产 1
>
> 属于 `yms-gate` 模块。也可以单独把这份复制给任何会写代码的 AI（Claude Code / Codex / 豆包电脑版 / WorkBuddy）。

## 它做什么，不做什么

- 做：按你的策略档案生成一个单文件的本地操盘台（一个 `index.html`，双击就在浏览器打开）：决策台管一笔交易的一生，计划台管今天和明天做什么；门禁、仓位上限、类型锁定这些规则写死在代码里。导出的账本能直接被 `yms-review` 读。
- 不做：不接任何券商接口，不联网，不自动下单。真实下单你自己在手机券商 App 上点——这道物理阻尼是刻意留的。

## 前置检查

| 要读 | 默认路径 | 用来做什么 | 缺了怎么办 |
|:---|:---|:---|:---|
| 策略档案 | `01_我的投资框架/Strategy_Profile.md` | 交易类型 = 你的机会分类；每类的默认计划周期、单只仓位上限、能否亏损加仓 | 没有 → 用「长期持有 / 波段 / 短线」三类占位，并在设置页提示「这些类型不是你写的，先跑 yms-setup 的策略档案」 |
| 长期规则 | `01_我的投资框架/长期规则.md` | 写死进代码的红线 | 没有就用下面的默认硬规则 |
| 已有操盘台 | `04_决策与交易记录/操盘台/index.html` | 有就是「改」，不是「重做」 | 改之前先把旧文件复制一份 `index_YYYYMMDD.html` |

## 步骤

1. **问我一个问题**：你最常在哪一步变形？（盘中冲动开仓 / 亏损加仓 / 拿不住 / 止损一放再放 / 别的）。答案决定哪条规则做成「拦截」，哪条做成「提醒」。
2. **把档案里的参数填进下面的需求**：交易类型、每类默认周期、每类仓位上限、是否允许亏损加仓。
3. **生成单个 `index.html`**，写到 `04_决策与交易记录/操盘台/index.html`。
4. **自测**：能打开浏览器的，打开一次，新建一笔交易、走一遍门禁、导出一次账本，确认没有报错；不能打开的，告诉我怎么测。
5. **告诉我三件事**：数据存在哪（浏览器本地存储，换浏览器就没了）、多久备份一次（建议每周导出一次 JSON）、导出的账本放到哪（`04_决策与交易记录/`）。

## 需求（发给写代码的 AI，方括号按档案填）

```markdown
请用 HTML5 + 原生 JavaScript + CSS 实现一个【单文件轻量投资操盘台】，输出可以直接在浏览器运行的单个 index.html。

【一、技术约束】
1. 严格单文件：HTML、CSS、JS 全部内嵌，不依赖任何框架和 CDN，不发任何网络请求；
2. 数据存本地：localStorage 存两张表（trades_db 交易生命周期，plans_db 日频计划），刷新不丢；
3. 顶部常驻：「备份数据（导出 JSON）」「恢复备份（导入 JSON）」「导出 Markdown 账本」「导出成交 CSV」；
4. 视觉：极简清晰。暖米底 #f7f4ee、面板白 #ffffff、文字 #24221f、强调色赤褐 #a6533c、绿色 #2f7857，不要花哨动画；
5. 常驻提示：「本工具不连接任何券商接口，真实下单请在券商 App 手动操作」。

【二、两个工作区（顶部 Tab 切换），标注流向：「决策台建立交易逻辑 → 计划台承接日频执行」】

▶ 工作区 1：买卖决策台（管一笔交易的一生）
1. 新建交易：标的名称、代码、交易类型（[档案里的机会分类]）、计划持有周期（按类型带出默认值 [每类默认周期]）、买入理由、认错条件、计划仓位（占总资金 %）、初始止损价；
   交易类型、计划持有周期、认错条件、初始止损价为必填，缺一项不允许提交；
   计划仓位超过该类型上限（[每类单只仓位上限]）不允许提交。
2. 状态：计划中 → 建仓中 → 持仓中 → 已平仓；另有「已作废」。
   卡片显示：代码、类型、已持有天数 / 计划周期、状态、成本价、持仓股数、止损价、认错条件。
3. 事件（点击弹出表单，只追加）：
   - 分批成交：日期、股数、成交价、费用 → 按加权平均重算成本；由我手动选「继续建仓」或「建仓完成」，第一笔成交不自动算建完；
   - 加仓：成交价低于当前持仓均价时弹窗：「这是事先写好的分批计划吗？」选「否」→ [档案：不允许亏损加仓 → 拦截 / 允许 → 记一条「亏损加仓」警告]；
   - 改计划：只改计划仓位，必须写理由；
   - 调整止损：新止损比初始止损更宽（多头下调）时拦截，提示「止损不放宽」；
   - 止盈 / 止损 / 减仓：卖出股数和价格 → 扣减持仓；
   - 平仓：卖出价必填，转入「已平仓」，记录实际持有天数与计划周期的差异；
   - 复核：写新的看法（原始理由不变）；
   - 作废：只允许零成交的计划单作废，必须写原因。
4. 锁定：原始买入理由、交易类型、计划周期在第一次成交后锁定，不允许修改，只能追加「复核」事件。

▶ 工作区 2：交易计划台（收盘后定计划，盘中只执行）
1. 计划录入：只能关联决策台已有的交易，设定明日计划：价格区间、执行条件、仓位比例；
2. 买入门禁四问：点击「锁定并生成执行单」时强制弹窗，四项全部勾选才能提交：
   [ ] ① 动机：是收盘后计划好的，还是卖飞 / 踏空之后的报复性补偿、盘中临时起意？
   [ ] ② 审计：止损价、仓位占比、明天低开怎么办，逐条确认了吗？
   [ ] ③ 时机：非得今天买吗？明天再买行不行？是不是 FOMO？
   [ ] ④ 周期与认错：这笔是哪一类交易、打算拿多久、什么条件下认错？（自动带出决策台填写的内容，让我再确认一遍）
3. 门禁没通过时，在审计日志里记一条「被拦截」，不当作交易事件；
4. 今日执行看板：大字显示价格区间与止损；「已在券商执行」和「作废」按钮；
5. 行为审计日志（底部折叠）：每次计划锁定、门禁通过 / 被拦截、执行确认、各种拦截的时间，只追加不修改。

【三、导出格式（固定，复盘工具要读）】
1. 成交 CSV，UTF-8，表头固定为：date,time,code,name,side,qty,price,fee,plan_id
   side 填「买」或「卖」；plan_id 填这笔交易的编号。
2. Markdown 账本，每笔交易一节：
   ## <代码> <名称> · <类型> · 计划周期 <> · 编号 <plan_id>
   - 建档：YYYY-MM-DD · 买入理由：…… · 认错条件：…… · 初始止损：…… · 计划仓位：x%
   - 事件：
     - YYYY-MM-DD 分批成交 <股数>@<价格> · 继续建仓 / 建仓完成
     - YYYY-MM-DD 调整止损 <旧> → <新> · 理由
     - YYYY-MM-DD 亏损加仓警告 / 被拦截 · 原因
     - YYYY-MM-DD 平仓 @<价格> · 实际持有 N 天 / 计划 <>
3. 审计日志单独导出一节「## 门禁与拦截」，每行：时间 · 标的 · 通过 / 被拦截 · 原因。

【四、输出要求】
直接输出完整、不截断、带注释的单个 index.html。响应式布局正常，localStorage 读写健壮（读失败时提示，不清空数据）。
```

## 输出

- `04_决策与交易记录/操盘台/index.html`
- 对话里列出：这次写死了哪些规则（拦截）、哪些只是提醒，分别来自档案的哪一条。

## 红线

- 生成的操盘台不发任何网络请求，不接券商接口。
- 写死的规则只来自我的档案和长期规则，不替我加我没写过的限制；我没写的，做成提醒，不做成拦截。
- 改已有操盘台前先备份旧文件；导出格式不随手改（复盘要读）。

## 我自己的样本

我自己用的那版，后来从单文件长成了本地一个小服务加两个页面，账本直接写进本地 Markdown。迭代下来最值得照抄的几条设计：

| 设计 | 为什么 |
|---|---|
| 原始买入理由只写一次，之后只能追加事件 | 事后你没法偷偷改写「我当初是怎么想的」，复盘才对得上 |
| 门禁没通过而硬点按钮，也记一笔「被拦截」 | 绕过门禁的次数本身就是复盘最重要的数据之一 |
| 区分「建仓中」和「持仓中」 | 计划买 100%，现实往往分三笔。第一笔成交就算建完，剩下的计划就从系统里消失了 |
| 区分「改计划」和「作废」 | 论点变弱想少买是「改主意」，要留痕；标的填错才是「作废」。混用会洗掉整条认知链 |

起步用单文件就够了：不装 Node.js、不配数据库，双击就能用。
