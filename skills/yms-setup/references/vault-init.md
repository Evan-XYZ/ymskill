# 建文件夹 · vault-init

> 聊天记录不是资产，文件夹才是。先给你的投资判断找一个 AI 读得懂、换工具也带得走的家。
> 来自《AI 投资指南》02 基建篇 §六 · 可带走资产一
>
> 属于 `yms-setup` 模块。也可以单独把这份复制进能读写本地文件的 AI 里用。

## 它做什么，不做什么

- 做：在你选的位置建一个本地 Markdown 投资文件夹：标准目录、给 Agent 的说明书、导航页、三份框架模板、`.gitignore` 和 `.env.example`；建完接着帮你写第一版策略档案。
- 不做：不覆盖你已有的任何文件，不移动你的旧笔记，不在文件里写任何真实密钥。

## 前置检查

| 要确认 | 怎么确认 | 情况不对怎么办 |
|:---|:---|:---|
| 建在哪 | 问我要一个路径 | 我没给就停，不默认建在当前目录 |
| 那里是不是已经有东西 | 列一下目标目录 | 已经有自己的投资笔记（比如 YMOS、Obsidian 库）→ 走下面的「已有文件夹」分支 |
| 我用哪个 Agent | 问我 | Claude Code 读 `CLAUDE.md`，Codex 读 `AGENTS.md`，其他工具读 `README.md` |

## 步骤：新文件夹

1. 建目录（下面就是完整清单；仓库里的 `docs/资产文件夹规范.md` 有每个目录的说明，装成 Skill 时本地不一定有，以这里为准）：

```text
01_我的投资框架/
02_研究档案/
03_每日观测/核实记录/
03_每日观测/传导推演/
04_决策与交易记录/操盘台/
04_决策与交易记录/券商导出/
05_复盘/单笔归因/
05_复盘/规则变更提案/
05_复盘/数据/
06_BrainStorm/原始想法/
06_BrainStorm/动作记录/
06_BrainStorm/Insight/
06_BrainStorm/感悟归档/短期灵感/
06_BrainStorm/感悟归档/长期框架/
06_BrainStorm/感悟归档/执行清单/
06_BrainStorm/回看/
06_BrainStorm/状态快照/
06_BrainStorm/历史资料/原始资料/
06_BrainStorm/历史资料/梳理/
```

   `06_BrainStorm/` 里的 `MEMORY.md` 和 `STATUS.md`，第一次用 `yms-brainstorm` 时再按它的模板建。`07_主控/` 先不建。等你有几条流程每天在跑、触发它们成了负担，再用 `yms-autopilot` 建。

2. 按 `templates/` 生成文件：

| 文件 | 模板 | 说明 |
|:---|:---|:---|
| `AGENTS.md` | `templates/AGENTS.md` | 给 Agent 的说明书。用 Claude Code 的，再建一个 `CLAUDE.md`，正文只写一行「先读 AGENTS.md」（或用 `@AGENTS.md` 引用，以官方最新用法为准） |
| `00_导航.md` | `templates/00_导航.md` | 每个目录一句话 |
| `01_我的投资框架/Strategy_Profile.md` | `templates/Strategy_Profile.md` | 全部留 `【待填】`，下一步再填 |
| `01_我的投资框架/观测清单.md` | `templates/观测清单.md` | 同上 |
| `01_我的投资框架/长期规则.md` | `templates/长期规则.md` | 红线那几条默认写好，其余 `【待填】` |
| `.gitignore` | 见下 | |
| `.env.example` | 见下 | 只写占位，不写真实值 |

```text
# .gitignore
.env
*secret*
04_决策与交易记录/券商导出/
05_复盘/数据/
06_BrainStorm/历史资料/原始资料/
```

```text
# .env.example
ANTHROPIC_API_KEY=
OPENAI_API_KEY=
DEEPSEEK_API_KEY=
```

3. 列出建好的清单，然后问我：「要不要现在花 15 分钟，把第一版策略档案写出来？」我说要，就转到 `strategy-profile`。

## 步骤：已有文件夹

不改目录，只加一段路径映射。

1. 读一遍目录结构和已有的总说明文件，猜出每一项对应哪里：

```markdown
## 路径映射
- Strategy_Profile = <你的路径>
- 观测清单 = <你的路径>
- 长期规则 = <你的路径>
- 研究档案 = <你的路径>
- 每日观测 = <你的路径>
- 交易记录 = <你的路径>
- 复盘 = <你的路径>
- BrainStorm = <你的路径>
- 主控 = <你的路径>
```

   **已经在用 YMOS 的**（根目录有 `总入口暗号.md`）：先看根目录有没有 `YMSKILL_ADAPTER.md`。有，就以它为准，它写了分工、路径映射和产物位置；没有（老版本 YMOS 还没补上它），用下面这份内置映射，路径映射和写之前三条与它一字不差（分工表见各模块的「在 YMOS 文件夹里」）。两种情况都按实际目录核对一遍，找不到的项写「没有」：

   ```markdown
   ## 路径映射（YMOS）
   - Strategy_Profile = Brain/策略配置/当前策略_Profile.md
   - 观测清单 = 持仓与关注/当前关注方向与投资偏好.md（只有占位、没填关注方向的空模板，按「没有」处理）
   - 长期规则 = 当前策略_Profile 里的红线和门禁部分；Console/rules.json 只是它在操盘台的投影，冲突时以 Profile 为准
   - 研究档案 = 持仓与关注/持仓/<标的>/、持仓与关注/动态Watchlist/<标的>/（只读已有的；新建按 持仓与关注/_模板_单标的/，先问用户）
     - 两把尺子、核心资产七问、反向 DCF、财报叙事：标的已有目录的，写进那个目录；没有的，写到 Brain/策略分析/ymskill/<名称>.md
   - 每日观测 = Eyes/市场洞察/、Eyes/投资雷达/
     - 事件登记 = Eyes/事件登记.md
     - 核实记录 = Eyes/核实记录/
     - 传导推演 = Eyes/传导推演/
   - 交易记录 = Brain/交易计划/、Brain/买入卖出决策/、Brain/决策审计/（都由 Console 写，只读）
     - 门禁日志（只在用户点名 /yms-gate 时）= Brain/决策审计/门禁日志.md（这个目录里只有这一份由 ymskill 追加）
     - 券商导出 = Brain/内核审计/数据/券商导出/
   - 复盘 = Brain/内核审计/
     - 持有期复盘、纪律体检报告、回看台账、回看汇总 = Brain/内核审计/ 下同名文件
     - 标准化成交数据 = Brain/内核审计/数据/
   - BrainStorm = BrainStorm/
     - 原始想法 = BrainStorm/每日头脑风暴/Raw_Thoughts/
     - Insight = BrainStorm/Summarized_Insights/
     - 感悟归档 = BrainStorm/投资感悟归档/（短期灵感/、长期框架/、执行清单/）
     - MEMORY.md = BrainStorm/MEMORY.md；STATUS.md = BrainStorm/状态机/STATUS.md
     - 状态快照 = BrainStorm/状态机/快照/
     - 动作记录 = BrainStorm/动作记录/
     - 回看 = BrainStorm/回看/
     - 历史资料 = BrainStorm/历史投资资料/（原始资料/、索引与梳理/）
   - 主控 = Agents/
     - 交接 = Agents/交接/；回执 = Agents/回执/；心跳日志 = Agents/心跳日志/
     - 全局状态 = Agents/全局状态.md；机会卡 = Agents/机会卡/
   ```

   分工：用户说的话在 `总入口暗号.md` 里有对应暗号的（每日观测、策略内核、买卖门禁和操盘台、平仓复盘、头脑风暴、历史资料、定时任务），照旧用 YMOS 的暗号；ymskill 只补 YMOS 没有的动作，产物写进上面的目录；用户点名 `/yms-*` 才用 ymskill 的版本，产物仍写进上面的目录。两边说法冲突时，以 YMOS 里用户确认过的 Profile 和状态机为准。YMOS 里有、映射里没有的目录（比如 `Eyes/` 下的热门观察），这套 Skill 不读也不改。

   写之前三条：

   1. **ymskill 自己的产物位置**（核实记录、传导推演、事件登记、`Brain/策略分析/ymskill/`、门禁日志、`Brain/内核审计/` 下的数据和复盘文件、动作记录、回看、状态快照、`Agents/` 下的交接、回执、心跳日志、全局状态、机会卡）不存在就直接建，建完在回复里说一句建在哪。
   2. **YMOS 自己的文件**（Profile、观测清单、Console 写的交易记录）不存在或是空模板，说明那部分还没配置：引导用户说对应的 YMOS 暗号（「配置一下我的内核」「更新我的关注方向」），不自己建；当次的输出标「无档案对照」或「无观测清单对照」。
   3. **文件夹是 git 仓库的**（根目录有 `.git/`），第一次往上面这些位置写之前，看 `.gitignore` 有没有忽略它们。没有，就把下面几行给用户看，问要不要追加。交割单、复盘、核实记录都是个人数据，不该进仓库。

   ```gitignore
   # ymskill 写进 YMOS 的个人产物
   Eyes/核实记录/
   Eyes/传导推演/
   Eyes/事件登记.md
   Brain/策略分析/ymskill/
   Brain/内核审计/数据/
   Brain/内核审计/持有期复盘_*.md
   Brain/内核审计/纪律体检报告_*.md
   Brain/内核审计/回看台账.md
   Brain/内核审计/回看汇总_*.md
   BrainStorm/动作记录/
   BrainStorm/回看/
   BrainStorm/状态机/快照/
   Agents/交接/
   Agents/回执/
   Agents/心跳日志/
   Agents/机会卡/
   Agents/全局状态.md
   ```

2. 把这段给我看，对不上的让我改。找不到对应的项写「没有」，不要硬凑。
3. 我说「确认」后，追加到已有说明书的末尾。已有说明书里的其他内容一个字不改；没有说明书就按模板新建一份。
4. 映射里写「没有」的项，问我要不要按标准路径补建。

   YMOS 不走第 3、4 步：不追加说明书，不按标准路径补建。有 `YMSKILL_ADAPTER.md` 的，它就是说明书；没有的，每次直接用上面的内置映射，产物位置按「写之前三条」。

## 输出

- 新建或补上的文件和目录清单。
- 如果走的是已有文件夹分支，附上最终确认的路径映射。

## 红线

- 不覆盖、不移动、不删除任何已有文件。
- 不在任何文件里写真实的 API Key、账户号、密码。
- `01_我的投资框架/` 的三个文件只建模板，内容等我在 `strategy-profile` 里确认。

## 我自己的样本

我的文件夹叫 YMOS，目录是按我自己的三层（投研、策略、操盘）长出来的，和这里的标准目录不一样。所以才有路径映射这一段：Skill 读的是映射，不是死路径。你已经有自己的笔记库，就别为了这套东西搬家。
