# 沉淀 · distill

> 不是每次头脑风暴都要改策略。很多记录的价值，只是让你更理解自己、避免遗忘或事后合理化；少数真正站得住的，再一步步往上走。
> 来自《AI 投资指南》04 策略层 §七 · 06 进阶篇 §五
>
> 属于 `yms-brainstorm` 模块。也可以单独把这份复制进能读写本地文件的 AI 里用。

## 它做什么，不做什么

- 做：我说「把这个感悟沉淀下来」时，帮我判断它该去哪：长期记忆、短期灵感、长期框架、执行清单，还是走规则变更；按对应的模板起草，给我看，我确认才写。
- 不做：不替我决定一条感悟有没有用，不把感悟直接写成约束交易的规则，不因为一条感悟出现了很多次就说它「有效」。

## 前置检查

| 要读 | 默认路径 | 用来做什么 | 缺了怎么办 |
|:---|:---|:---|:---|
| 这条感悟的出处 | `06_BrainStorm/Insight/`、`原始想法/`，或 `05_复盘/` 里的复盘 | 保留来源 | 我直接口述的，先按 `capture` 存一份原话 |
| 长期记忆 | `06_BrainStorm/MEMORY.md` | 有没有说过类似的、有没有冲突 | 不存在就按 `templates/MEMORY.md` 建 |
| 感悟归档 | `06_BrainStorm/感悟归档/` | 已有的短期灵感、框架、清单 | 没有就新建目录 |
| 长期规则 | `01_我的投资框架/长期规则.md` | 判断它是不是已经是规则了 | 没有不阻断 |

## 去向怎么选

```text
一次想法、困惑、情绪              → 留在 Insight，继续观察（多数情况）
三个月后还成立的背景或认知        → 长期记忆 MEMORY
一笔交易或一件事换来的教训        → 短期灵感
几条短期灵感收敛出的判断链        → 长期框架
从框架拆出来、某个场景下要照做的   → 执行清单
暴露了现行规则的歧义或冲突        → 规则变更的线索（yms-review），不在这里改
```

判断标准写给我看，最后由我选。

## 步骤

1. 把这条感悟用我的原话写成一句。
2. 按上面的图建议一个去向，说明为什么；我选了再往下。
3. 按去向起草：

| 去向 | 写到 | 模板 | 起草时要做到 |
|:---|:---|:---|:---|
| 长期记忆 | `06_BrainStorm/MEMORY.md` 对应的一节 | `templates/MEMORY.md` | 带日期；放对一节（关于我 / 投资哲学与纪律 / 已验证的原则 / 认知节点 / 已证伪或已放弃 / 持续关注的问题）；「已验证的原则」只放被实盘反复验证过的 |
| 短期灵感 | `感悟归档/短期灵感/YYYY-MM-DD_<主题>.md` | `templates/短期灵感.md` | 分清是判断错了还是执行错了：判断错改框架，执行错改闸门 |
| 长期框架 | `感悟归档/长期框架/<框架名>.md` | `templates/长期框架.md` | 列出由哪几条短期灵感收敛而来；**边界一节必须写**；没有已验证样本的，状态写「候选」 |
| 执行清单 | `感悟归档/执行清单/<场景>.md` | `templates/执行清单.md` | 写清触发条件和上游框架；「明确不做的事」至少一条；状态写「候选」 |

4. 把草稿完整给我看，我说「确认」才写入。写进 MEMORY 的，同时在当天的 Insight 末尾记一行「已沉淀到 MEMORY · <哪一节>」。
5. 「已证伪 / 已放弃」这一节要主动问：这条感悟有没有推翻你以前相信过的东西？有的话，把旧的那条挪进去，写清「曾经认为 → 实际是 → 代价」。

## 什么时候可以去规则变更

框架或清单想变成真正约束交易的规则（门禁、红旗扫描会读的那种），先过这几条，再交给 `yms-review` 的规则变更：

- 来自多个独立案例，不是同一件事的重复描述；
- 写了反例和适用边界；
- 分清了问题出在判断、执行、规则冲突还是信息质量；
- 能写出「改错了会看到什么」和回滚办法。

主要证据来自感悟和旧日志的，提案要标「规则澄清型」，先试运行，不能声称交易结果已经验证。

## 输出

- 按去向写到对应文件；对话里附一句「沉淀到了哪、状态是什么（候选 / 已确认）」。

## 红线

- 没有我的「确认」，不写 MEMORY、不写框架和清单。
- 感悟归档里的东西都不具备门禁效力，只有经规则变更批准、写进 `长期规则.md` 的才算数。
- 不把示例里的参数复制进我的文件。
- 不给买卖建议。

## 我自己的样本

长期记忆里我最看重的一节是「已证伪 / 已放弃」。记下曾经相信、后来发现是错的东西，以及为什么。没有这一节，人会隔一年再信一次。

「两个目标用两把尺子」就是走这条路上来的：先是一次错过之后的 Insight 里的一条假设；后来那次错过代价够大，成了一条提案——「长期资产的理由不能用来挡事件波段」从一条局部规则改成全局自检。批了，现在在试运行，有复核日。
