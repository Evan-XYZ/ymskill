# 每日变化 · daily-delta

> 衡量一个投研系统好不好，不是每天推了多少条，而是替你挡掉了多少条。
> 来自《AI 投资指南》03 投研层 §五
>
> 属于 `yms-watch` 模块。也可以单独把这份复制进任何 AI 对话里用：把今天看到的新闻和昨天的观测一起贴进去。

## 它做什么，不做什么

- 做：每天先把昨天写下的「接下来怎么核」逐条对真值，再按你的观测清单只写实质变化；每条变化压成两句话，事件层和对我层分开；明天的确定性事件提前写好三岔口。
- 不做：不播行情，不做单日涨跌归因，不给买卖建议。没有够分量的事就说没有。

## 前置检查

| 要读 | 默认路径 | 必需字段 | 缺了怎么办 |
|:---|:---|:---|:---|
| 观测清单 | `01_我的投资框架/观测清单.md` | 关注方向、信源及级别、什么才算变化 | **停下**，提示先跑 `yms-setup` 的观测清单 |
| 上一份观测 | `03_每日观测/` 里最近的 `*_每日观测.md` | 「接下来怎么核」「仍待核」「三岔口」 | 第一次跑，跳过第 1 步 |
| 策略档案 | `01_我的投资框架/Strategy_Profile.md` | 各目标和关注方向 | 没有就不写对我层，写明「无档案，对我层留空」 |

## 步骤

**1. 先对昨天**
把上一份观测里「接下来怎么核」和「仍待核」逐条对真值：
- 有结果的：写成今天的一条，标「证实 / 证伪」，附来源和级别；
- 还没结果的：原样挪到今天末尾的「仍待核」；连续挂了 5 个交易日的，问我还要不要继续核。

**2. 对三岔口**
上一份观测里写过三岔口的确定性事件（议息、CPI、核心财报），今天出结果了，就直接比对落在哪一岔，再写那一岔事先写好的「看什么」。

**3. 收信息，查信源**
- 按观测清单里的信源收今天的信息（我也可能直接贴给你）；
- 记下哪些信源今天没取到；连续失败 3 次的，在文件开头标红；
- 每条先查两件事：来源级别；第一次公开是什么时候（旧闻翻新不进今天）。

**4. 过滤：和上一次相比，是不是实质变化**

```text
[新信息] ─→ 和上一次记录相比，是否发生实质变化？
   ├─ 否（常规小幅波动 / 研报炒冷饭 / C 级噪音）─→ 不写，只在末尾记一个条数
   └─ 是（S / A 级事件 / 趋势阶段换档 / 关键位置被打破 / 观测清单里我自己加的）─→ 进今天的变化
```

S / A 级事件，就算没打到我任何关注方向，也要写。

**5. 初评分量**
对留下来的每一条，按 `event-grading` 的口径给一行初评。定评要等开过原件。

**6. 两句话压缩**

```text
【第一句 · 事实与定性】发生了什么（数据 / 事件 + 来源级别），属于超预期、不及还是预期内。
【第二句 · 关联与下一步】它打到的是哪个变量（估值 / 业绩 / 催化 / 位置），接下来看什么、怎么核、什么时候能确认。
```

第二句的动词只用 看 / 核 / 等 / 对照。

**7. 方向和阶段**
观测清单里的每个关注方向，写它现在处在哪个阶段：新高 / 新低 / 底部震荡 / 顶部震荡，和上一次比有没有换档。不写「今天涨了几个点因为什么」。

**8. 对我层**
最后单独一节：今天的变化和我策略档案里的哪个目标、哪个关注方向有关系。先把事情说清楚，再问跟我有什么关系，顺序不能反。

**9. 留给明天**
- 「接下来怎么核」：每条写成一个可以对真值的待办；
- 明天有确定性事件的，今天先写三岔口：超预期 / 符合 / 不及，各自看什么。

## 输出

写到 `03_每日观测/YYYY-MM-DD_每日观测.md`：

```markdown
# YYYY-MM-DD 每日观测
> 生成时间：HH:MM（时区）· 信源：成功 N / 失败 M（<哪几个>）· 补跑：<是/否>

## 一、昨天待核的，今天对上了吗
- <待核项> → 证实 / 证伪：<一句>（来源 · S/A/B）

## 二、今天的变化（事件层）
### 1. <一句话标题>
势能（初评）：<级别> · 范围 <> · 触达 <> · 持续 <> · 阶段 <> · 资金 待看
- 事实与定性：……（来源：<名称或链接> · S/A/B）
- 关联与下一步：打到 <变量>；<看 / 核 / 等 / 对照>……
- 冷水：<一句：这件事可能没那么重要的理由>

（没有就写：今日无需推演。）

## 三、方向和阶段
| 关注方向 | 阶段 | 和上次比 |
|:---|:---|:---|

## 四、对我层
- ……

## 五、接下来怎么核
- [ ] ……

## 六、明天的确定性事件 · 三岔口
| 事件 | 超预期看什么 | 符合看什么 | 不及看什么 |
|:---|:---|:---|:---|

## 仍待核
- ……

> 今天过滤掉 <N> 条（常规波动 / 炒冷饭 / C 级）。
```

- 初评为 S / A 的事件，按 `event-grading` 追加到 `03_每日观测/事件登记.md`。
- 漏了一天不逐天补，补最近一期，开头写「补跑」。

## 红线

- 不给买卖建议，不预测涨跌，不写目标价。
- 事件层不出现「我」。
- 二手说法不当事实；摘要和原始数据对不上时，以原始数据为准。
- 不为了显得有内容而硬凑变化。

## 我自己的样本

有一次我的摘要报告写「AI 板块缺席新高」，但原始新高名单里，当天恰好有一家 AI 属性的公司创了 60 日新高。摘要错了一句，下游两份报告跟着错。所以规矩里有一条：系统自己算出的信号，以原始数据表为准，不用下游的摘要句。

「连续剧，不是每天从零开始」这一条是我用得最久的：每天第一步先对昨天的待核清单，系统盯的永远是变化——昨天的假设今天被证实还是被证伪了。
